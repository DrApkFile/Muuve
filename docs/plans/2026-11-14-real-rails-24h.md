> Muuve's devnet test-dollar faucet (no US dollar accounts yet); Cleva is shown as coming

Drafted 14 November 2026. A plan, not yet built. Owner decisions are marked **Decide**.

## What "working" can mean in 24 hours

Every piece below can run against **real provider APIs in their sandbox or test modes** within
a day. Moving **real money** cannot: it needs provider business verification (KYB), a funded
naira balance, mainnet, and Nigerian compliance sign-off. That takes days to weeks, and
none of it is code. So the 24-hour target is: real APIs, real sign-ups, real webhooks, real
bank-name lookups, with sandbox dollars and test-mode payouts. The chain stays on devnet.

## The Cleva question (Decide first)

Cleva has no public developer API that we could find: its site documents consumer
accounts, not partner endpoints. "Only Cleva" therefore can't be wired today unless
Cleva gives us API access at the event. Options:

1. **Recommended:** build the two provider interfaces now (`UsdAccountProvider`,
   `PayoutProvider`), wire **Bridge sandbox** and **Paystack test mode** behind them as
   working stand-ins, and pitch Cleva as the production partner that slots into the same
   interfaces. Ask Cleva at the event for API access.
2. Keep the Cleva mock and only build email sign-in. Nothing real moves.

The rest of this plan assumes option 1.

## Design in one paragraph

An email user gets a Privy embedded wallet at sign-up, and that address becomes
`users.wallet_address`, so balance, send, recall and cash-out work as they do for wallet
users today. A US bank deposit arrives at Bridge; Bridge's webhook tells us the amount and
we credit the user's balance by minting the same amount of devnet test dollars (the existing
funding path), keyed by Bridge's event ID so it never double-credits. "Deposit from a wallet"
is a separate, optional screen: connect Phantom and transfer test dollars into the Muuve
address. Cash-out keeps the existing escrow → treasury → payout pipeline, with Paystack
replacing the mock provider.

## Work plan

Hour marks are from kickoff. One builder plus Claude; DrApkFile owns accounts and deploys.

### 0–1h: accounts and keys (DrApkFile)

- Privy dashboard: enable **Email** login and Solana embedded wallets created on login.
  Check it can run alongside the existing custom-auth setup used for keep-in-dollars.
- Bridge: sign up, get the sandbox API key, set the webhook URL to
  `https://muuve.onrender.com/api/webhooks/bridge`, note the webhook signing key.
- Paystack: sign up, copy test secret key, set the test webhook URL to
  `https://muuve.onrender.com/api/webhooks/paystack`.
- Add the keys to Render's environment. Names only go in `.env.example`.

### 1–6h: email sign-in

- Migration `007_email_accounts.sql`: `users.email` (unique), `users.privy_user_id`
  (unique), allow `auth_origin='email'`.
- Client: add `@privy-io/react-auth`. "Continue with email" on `/start` uses Privy's email
  code flow. The embedded wallet joins `lib/wallet.tsx` as a signer, so the rest of the app
  can use it like Phantom.
- Server: `POST /api/auth/email` verifies the Privy access token, finds or creates the user,
  stores the embedded wallet address, and issues our normal session cookie. The phone-link
  step and the phone gate on sending stay as they are.
- Tests: token verification (bad, expired, wrong app), one user per email, wallet address
  saved.

### 6–8h: deposit from a connected wallet

- "Add money → From a wallet": connect Phantom, enter an amount. The server prepares a
  test-dollar transfer from Phantom to the user's Muuve address through the existing
  operations pipeline (Muuve pays the fee), Phantom signs, and the balance updates when it
  finalizes.

### 8–15h: US dollar account (Bridge sandbox)

- `providers/usd-account.ts`: `UsdAccountProvider` interface with `bridge` and `mock`
  implementations.
- `POST /api/usd-account`: create the Bridge customer and a hosted KYC link. Once KYC is
  approved, create a virtual account (USD in, Solana USDC out to the user's address) and
  store its ID.
- `GET /api/usd-account`: status plus account details (bank, routing and account number,
  beneficiary name) for the "Add money → US bank account" screen.
- `POST /api/webhooks/bridge`: verify the signature, then credit the deposit once per event
  by minting devnet test dollars to the user. Record it in the activity timeline.
- Migration `008_usd_accounts.sql`: `usd_accounts` and `usd_deposits` tables, with
  idempotency on the provider event ID.
- To check: whether Bridge sandbox can simulate a deposit into a virtual account. If not,
  add a devnet-only "simulate deposit" button that drives the same handler.

### 15–21h: naira payouts (Paystack test mode)

- `providers/payout.ts`: `PaystackPayoutProvider` implementing `PayoutProvider`:
  - create a transfer recipient, then a transfer, with our payout key as the reference so
    retries are idempotent;
  - `status()` checks the transfer by reference.
- Replace `mockBankDirectory` with Paystack's bank list and account-name lookup.
- `POST /api/webhooks/paystack`: verify the HMAC-SHA512 signature, then mark payouts paid
  or failed through the existing state machine (failed → refund path).
- Config: `PAYOUT_PROVIDER` becomes `mock | paystack`; screens show "Test payout"
  instead of "Simulated" when it's Paystack test mode.

### 21–24h: end to end, deploy, demo script

- Full run on the hosted stack:
  1. Email sign-up.
  2. Phone link.
  3. US account KYC and a sandbox deposit.
  4. Balance.
  5. A send link, then a claim.
  6. A Paystack test cash-out and webhook to paid.
  7. A wallet deposit.
- `pnpm check`, API and database tests, then a Render deploy and a Vercel deploy.
- Update the handoff doc and the demo script.

## Risks

- **Privy:** the email login and custom auth combination may need a second Privy app.
  Check in hour 0.
- **Bridge access:** sandbox keys may need approval; if not available by hour 8, skip it
  and present the US account screen on the `mock` provider.
- **Bridge stablecoin:** Bridge delivers USDC; our links hold USDT. Real money needs a
  USDC→USDT swap or USDC links. Not relevant on devnet.
- **Going live:**
  - Paystack live transfers need a verified Nigerian business and a funded naira balance.
  - Bridge live needs KYB approval.
  - Both need compliance review, because Muuve's treasury briefly holds funds on cash-out.
